# Step 1: checked build foundation

Date: 2026-11-12. Work package: BASE-001, initial desktop/headless baseline. Status: implemented and verified on Linux x86-64. P1 overall remains open; this is not completion of networking, Android voice or physical-phone validation.

## What changed

- Added `toolchain.lock.json`: Godot 4.7.2 Standard, official Linux archive and executable checksums, matching template archive metadata, authoring/reference Android versions and explicit absence of selected native/voice addons.
- Added `tools/bootstrap_godot.py`: downloads or reuses the exact Linux build, verifies its size/checksums, installs only the expected archive member and checks the cached executable before reuse.
- Added `tools/validate_project.py`: rejects another engine, copies source into a clean temporary project, imports assets, runs the existing regression checks, exports a pack, checks excluded development files and starts the packaged game from an empty project directory.
- The Android build helper now uses the same engine guard. Its established SDK/signing setup remains required; this step did not export another APK.
- Added a desktop pack preset. The island main scene, movement scripts and models are unchanged. The prior island baseline remains on `archive/island-v0.2.0`.

The workspace's default engine was 4.6.3. It is not used for project validation/export. The pinned engine reports `4.7.2.stable.official.ed1daf0bf`.

## Repeat it

Use Python 3.11 or newer on the Linux x86-64 build host:

```bash
python tools/bootstrap_godot.py
python tools/validate_project.py
```

To reuse a downloaded archive, supply `--archive /path/to/Godot_v4.7.2-stable_linux.x86_64.zip` to the bootstrap command. To use an explicitly installed engine, run `python tools/validate_project.py --godot /path/to/godot`. The engine must match the pin; the official executable checksum is also enforced on the Linux x86-64 host. Other desktop bootstrap/install paths have not been validated in this step.

Local logs, exported pack and `report.json` go under `builds/baseline/`; they are not committed. A failed check returns nonzero and retains a report/log rather than marking the milestone successful.
